**Function 1: analyze_heading_structure (CONT-01)**
Signature: `pub fn analyze_heading_structure(html: &Html) -> AnalysisResult`

- Select all heading elements in DOM order using: `Selector::parse("h1, h2, h3, h4, h5, h6").expect("valid selector")`
- Extract level numbers as `Vec<u8>`:
  ```rust
  let levels: Vec<u8> = html.select(&heading_sel)
      .map(|el| {
          el.value().name()
            .chars().last().unwrap()
            .to_digit(10).unwrap() as u8
      })
      .collect();
  ```
- If levels is empty → Pass: check "cont-heading-structure", message "No headings found on page (no hierarchy to validate)", recommendation "Consider adding a heading structure (H1 for title, H2 for sections) to improve content organization for AI crawlers"

- Check for skipped levels:
  ```rust
  let mut prev = 0u8;
  let mut skip_found = false;
  for &level in &levels {
      if prev > 0 && level > prev + 1 {
          skip_found = true;
          break;
      }
      prev = level;
  }
  ```
  - skip_found is true → Fail: check "cont-heading-structure", message "Heading hierarchy has skipped levels (e.g., H1 followed by H3)", recommendation "Fix heading nesting: each heading level should increment by one (H1 → H2 → H3). Skipped levels confuse screen readers and AI content parsers that infer document structure from headings"
  - No skip → Pass: check "cont-heading-structure", message "Heading hierarchy is correctly nested with no skipped levels"

**Function 2: analyze_alt_text (CONT-04)**
Signature: `pub fn analyze_alt_text(html: &Html) -> AnalysisResult`

- Select all img elements: `Selector::parse("img").expect("valid selector")`
- Count total images and images with absent or empty alt text:
  ```rust
  let mut total = 0usize;
  let mut missing = 0usize;
  for img in html.select(&img_sel) {
      total += 1;
      match img.value().attr("alt") {
          None => missing += 1,
          Some(v) if v.trim().is_empty() => missing += 1,
          _ => {}
      }
  }
  ```
- total == 0 → Pass: check "cont-alt-text", message "No images found on page", recommendation "When adding images, always include descriptive alt text for accessibility and AI indexing"
- missing == 0 → Pass: check "cont-alt-text", message "All {total} image(s) have alt text"
- missing > 0 → Fail: check "cont-alt-text", message "{missing} of {total} image(s) are missing alt text", recommendation "Add descriptive alt text to all {missing} image(s). Alt text is the primary signal AI search engines use to understand image content and improve page relevance"

**Function 3: analyze_json_ld (CONT-02)**
Signature: `pub fn analyze_json_ld(html: &Html) -> AnalysisResult`

Per research scope (Pattern 5): Validate that JSON-LD blocks are (1) valid JSON, (2) have `@type`, (3) have `@context` containing "schema.org". Full Schema.org type-specific validation is GEO territory (Phase 3).

- Selector: `Selector::parse(r#"script[type="application/ld+json"]"#).expect("valid selector")`
- Collect all JSON-LD script elements
- If none found:
  - Warn: check "cont-json-ld", message "No JSON-LD schema markup found on page", recommendation "Add JSON-LD schema markup (e.g., Article, Product, FAQPage) to help AI search engines understand your content type and structure. Schema markup is a key signal for AI-powered search results"
- If found, validate each block:
  - Parse with `serde_json::from_str::<Value>(&text)`:
    - Err → Fail immediately: check "cont-json-ld", message "JSON-LD block contains malformed JSON", recommendation "Fix the JSON syntax in your schema markup. Use https://validator.schema.org/ to validate before deploying"
    - Ok(val):
      - No `@type` key → Fail: check "cont-json-ld", message "JSON-LD block is missing required @type property", recommendation "Add an @type property to your JSON-LD (e.g., \"@type\": \"Article\"). @type tells search engines what kind of content this is"
      - Has `@type` but `@context` is absent or does not contain "schema.org" → Warn: check "cont-json-ld", message "JSON-LD block has @type but @context does not reference schema.org", recommendation "Set @context to \"https://schema.org\" to use the Schema.org vocabulary — this is required for search engine recognition"
      - Has valid `@type` and `@context` with "schema.org" → Pass: check "cont-json-ld", message "JSON-LD schema markup is valid with @type and schema.org context"
  - Return on first non-passing result (early exit on first failure/warn)
  - If all blocks pass → Pass
