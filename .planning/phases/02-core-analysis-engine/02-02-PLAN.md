**Function 2: analyze_meta_tags (TECH-03)**
Signature: `pub fn analyze_meta_tags(html: &Html) -> Vec<AnalysisResult>`
Returns 2 results (one for title, one for description):

Title check ("tech-meta-title", severity: critical):
- Selector: `Selector::parse("title").expect("valid selector")`
- Get text: `.next().map(|el| el.text().collect::<String>().trim().to_string())`
- Absent or empty → Fail: message "Page has no title tag", recommendation "Add a <title> tag with 50-60 characters describing the page content"
- 1-49 chars → Warn: message "Title is N chars (min 50)", recommendation "Expand title to 50-60 characters for optimal search snippet display"
- 50-60 chars → Pass: message "Title is N chars (optimal range 50-60)"
- 61+ chars → Fail: message "Title is N chars (max 60)", recommendation "Shorten title to 50-60 chars — truncation in search results reduces click-through rate"

Description check ("tech-meta-description", severity: warning):
- Selector: `Selector::parse(r#"meta[name="description"]"#).expect("valid selector")`
- Get content attr: `.next().and_then(|el| el.value().attr("content")).unwrap_or_default()`
- Empty/absent → Warn: message "Page has no meta description", recommendation "Add a meta description of 120-158 characters summarizing the page for search engines"
- 120-158 chars → Pass: message "Meta description is N chars (optimal range 120-158)"
- Outside range → Warn: message "Meta description is N chars (optimal: 120-158)", recommendation "Adjust meta description to 120-158 characters — this is the displayed snippet length in most search engines"

**Function 6: analyze_redirect_chains (TECH-02)**
Signature: `pub async fn analyze_redirect_chains(client: &reqwest::Client, url: &Url) -> AnalysisResult`

Note: The passed-in `client` is the main client from `main.rs` which follows redirects. For redirect DETECTION we need a custom policy client. Build it inside this function:

```rust
let redirect_client = reqwest::Client::builder()
    .redirect(reqwest::redirect::Policy::custom(|attempt| {
        if attempt.previous().len() >= 3 {
            attempt.error("too many redirects")
        } else {
            attempt.follow()
        }
    }))
    .timeout(Duration::from_secs(10))
    .user_agent(concat!(env!("CARGO_PKG_NAME"), "/", env!("CARGO_PKG_VERSION")))
    .build()
    .expect("failed to build redirect client");
```

Logic:
- Make a HEAD request (or GET if HEAD not supported) to `url.as_str()` using the redirect_client
- If response is Ok: compare `response.url()` to original url
  - If same → Pass: check "tech-redirect-chains", message "No redirects detected for this URL"
  - If different (1-2 hops, no error) → Pass: check "tech-redirect-chains", message "Single redirect to final URL (acceptable)"
- If Err and error message contains "too many redirects":
  - Fail: check "tech-redirect-chains", message "Redirect chain has 3 or more hops", recommendation "Reduce redirect chain to a single canonical redirect — each hop adds latency and dilutes link equity. Update links and canonicals to point directly to the final URL"
- If Err for other reasons (network, timeout):
  - Warn: check "tech-redirect-chains", message "Could not check redirect chain (request failed)", recommendation "Ensure the URL is accessible and retry"

  - Read body as text
  - Check if any line starts with "Sitemap:" (case-insensitive)
  - Has Sitemap: directive → Pass: check "tech-robots-txt", message "robots.txt found and contains Sitemap directive"
  - No Sitemap: directive → Warn: check "tech-robots-txt", message "robots.txt found but missing Sitemap: directive", recommendation "Add 'Sitemap: https://yourdomain.com/sitemap.xml' to robots.txt so search engines can discover your sitemap"
