**mcp/src/index.ts** (per D-01, D-02, D-04, D-05, D-06, D-07, D-08):

First line MUST be `#!/usr/bin/env node` (shebang for npx execution, per Pitfall 5 from research).

Import `McpServer` from `@modelcontextprotocol/sdk/server/mcp.js` and `StdioServerTransport` from `@modelcontextprotocol/sdk/server/stdio.js`. Import `z` from `zod`. Import `execFile` from `node:child_process`, `promisify` from `node:util`, `resolve`/`dirname` from `node:path`, `fileURLToPath` from `node:url`, `existsSync` from `node:fs`.

Create `execFileAsync = promisify(execFile)`.

Create `getBinaryPath()` function:
- Compute `__dirname` via `dirname(fileURLToPath(import.meta.url))`
- Determine extension: `process.platform === "win32" ? ".exe" : ""`
- First check: `resolve(__dirname, "..", "bin", "geodaddy" + ext)` (installed via postinstall)
- Second check: `resolve(__dirname, "..", "..", "target", "release", "geodaddy" + ext)` (local dev via cargo build)
- Use `existsSync` to find which path exists. If neither, throw Error with message: `"geodaddy binary not found. Run 'cargo build --release' or reinstall the package."`

Create `McpServer` instance with `name: "geodaddy-mcp"` and `version: "0.1.0"`.

Register tool `"analyze_url"` (per D-04) with:
- `title`: `"Analyze URL for GEO/SEO"`
- `description`: `"Run geodaddy GEO/SEO analysis on a URL. Returns a JSON report with overall score (0-100), per-category scores (Technical, Content, GEO, Performance), per-page analysis results, and actionable fix recommendations for AI search engine optimization."`
- `inputSchema` with these Zod fields (per D-05, 1:1 mapping):
  - `url`: `z.string().describe("URL to analyze (supports http://localhost)")` -- required
  - `max_pages`: `z.number().int().positive().optional().describe("Enable site crawling, stop after N pages")`
  - `enable_js`: `z.boolean().optional().describe("Enable JavaScript rendering (downloads Chromium on first use)")`
  - `vitals`: `z.boolean().optional().describe("Measure Core Web Vitals (LCP, FCP, CLS, TTFB, TBT) via headless browser")`
  - `fail_under`: `z.number().min(0).max(100).optional().describe("Return error if overall score is below this threshold (0-100)")`
  - `beauty`: `z.boolean().optional().describe("Return colored human-readable output instead of JSON (note: disables JSON output)")`

Tool handler function (per D-06, D-07, D-08):
1. Build args array: start with `[url]`
2. If `max_pages !== undefined`, push `"--max-pages"` and `String(max_pages)`
3. If `enable_js === true`, push `"--enable-js"`
4. If `vitals === true`, push `"--vitals"`
5. If `fail_under !== undefined`, push `"--fail-under"` and `String(fail_under)`
6. If `beauty === true`, push `"--beauty"`
7. Call `execFileAsync(getBinaryPath(), args, { timeout: 120_000, maxBuffer: 10 * 1024 * 1024 })`
8. On success: return `{ content: [{ type: "text" as const, text: stdout }] }`
9. On error (catch block): extract `error.stderr || error.message || "Unknown error"`, return `{ content: [{ type: "text" as const, text: message }], isError: true }`

After tool registration, create `StdioServerTransport` and call `await server.connect(transport)`.

CRITICAL: Do NOT use `console.log()` anywhere in this file. Use `console.error()` only if debug logging is needed (per Pitfall 1 -- stdout is reserved for MCP JSON-RPC).
